**Status:** proposed design inference; actual task assignment and runtime benefit are unverified. The task/tool contract can assign a simulated function even where the analogous human job needs credentials; do not invent extra real-person steps.

## What function are we trying to preserve?

Assess and improve movement/function within physical-therapy practice.

The linked healthcare dossier contains the responsibilities, scoped decisions and evidence. This analysis does not upgrade its conditions or model contacts into universal facts.

## Specific question

Which mobility/rehabilitation facts support this referral and what local access rule is unknown?

## Provisional conclusion and reason

Candidate on-demand specialist with a specific question and bounded evidence view; proposal by default, not assumed case-finalization authority.

The previous audit did not establish a specific direct-access state rule.

Primary grouping: [W16 — Rehabilitation, nutrition and respiratory interfaces](../WORK_PACKAGES.md#w16). Request or summarize discipline-specific assessments and service needs.

## Can its work be merged?

Use a common referral/evidence adapter with discipline-specific capability selection; persistent workers only if workload and errors justify them.

**Boundary that must survive:** Different disciplines assess different functions and have different scope; one capability catalogue is not interchangeable clinical expertise.

A common work package is not proof that one employee may perform every activity, or that one persistent LLM is best. A shared adapter, a role mode and a separate worker are all alternatives.

## Information and output contract

Context from the prior proposed model: History/referral where required; Functional assessment and goals.

Potential work products from that model: Therapy plan/progress; Functional recommendations.

For a software invocation, add case/stage, source versions, explicit unknowns, allowed operations, requested output, current owner and stop condition. These are proposed internal fields, not verified API parameters or mandatory institutional forms.

## Counterexample and reconsideration

**Failure to detect:** The harness assumes either universal direct access or universal physician referral.

**Reason to split/revise the package:** A general specialist output substitutes nutrition, mobility, daily-function, communication or respiratory evidence for one another.

Test a mode-based owner and a bounded specialist/persistent-worker alternative against the same task-visible facts and declared resource constraint; preserve source, authority and completion distinctions. No such comparison has run.

## Remaining uncertainty and evidence

Professional clinical assessment and authorization/payment criteria are separate. Actual state/order rules are not nationally resolved.

**Prior applicability:** State/direct-access, order and payer requirements can differ; do not infer one universal physician-supervision hierarchy. No particular state direct-access rule was established in this audit; attempted V20 was unavailable and is not used as proof.

Source IDs in the prior dossier: B15, R30. These support the scoped healthcare context, not the new software partition. See the prior [source provenance](../../HealthcareRoles/SOURCE_PROVENANCE.md) for failed/dated/example evidence.

Related authority questions: Apply the explicit package/role boundaries; no additional decision power is inferred..
