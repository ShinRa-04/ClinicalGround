# O08 — Clinical-documentation-integrity specialist

[Role analysis index](../ROLE_ANALYSIS.md) · [Audited healthcare dossier](../../HealthcareRoles/roles/O08.md)

**Status:** proposed design inference; actual task assignment and runtime benefit are unverified. The task/tool contract can assign a simulated function even where the analogous human job needs credentials; do not invent extra real-person steps.

## What function are we trying to preserve?

Help clarify documentation needed to accurately represent the care provided.

The linked healthcare dossier contains the responsibilities, scoped decisions and evidence. This analysis does not upgrade its conditions or model contacts into universal facts.

## Specific question

Should an inconsistency trigger a clarification query rather than an automated repair?

## Provisional conclusion and reason

Candidate reusable evidence/checking capability; autonomous persistence needs a measured reason.

Documentation consistency review can be shared; substantive corrections require appropriate authorship.

Primary grouping: [W06 — Records, coding and documentation support](../WORK_PACKAGES.md#w06). Retrieve authentic records and identify coding/documentation questions with source attribution.

## Can its work be merged?

A bounded evidence-preparation capability can combine retrieval and consistency checks without multiple autonomous writers.

**Boundary that must survive:** Record release, coding interpretation, clinical clarification and authentication are distinct. Staff must not create unsupported clinical facts.

A common work package is not proof that one employee may perform every activity, or that one persistent LLM is best. A shared adapter, a role mode and a separate worker are all alternatives.

## Information and output contract

Context from the prior proposed model: Clinical record; Coding/denial question.

Potential work products from that model: Clarification query; Documentation-quality finding.

For a software invocation, add case/stage, source versions, explicit unknowns, allowed operations, requested output, current owner and stop condition. These are proposed internal fields, not verified API parameters or mandatory institutional forms.

## Counterexample and reconsideration

**Failure to detect:** The agent resolves a conflict by silently rewriting the clinical source.

**Reason to split/revise the package:** A merged evidence worker silently repairs a clinical fact instead of requesting clarification or preserving uncertainty.

Test a mode-based owner and a bounded specialist/persistent-worker alternative against the same task-visible facts and declared resource constraint; preserve source, authority and completion distinctions. No such comparison has run.

## Remaining uncertainty and evidence

Clinical author authentication and permitted correction remain setting-specific; clarification is not permission to invent diagnoses.

**Prior applicability:** Documentation improvement is not permission to rewrite clinical facts to match coverage criteria.
