## Resource and integration limits

- The Codex route has no verified strict output-token cap. A prompt hint and output-character limit do not equal token enforcement. Account usage can be consumed even when a case ends unresolved.
- Harness completion-call budgets are not exact counts of Codex-internal retries or network requests. Reported token fields are accumulated without inventing omitted metrics.
- Current compatibility is verified for the named local CLI build. Other versions/configuration policies need protocol tests and an explicit native check.
- Hash approval in the CLI applies to that invocation's observed file bytes; persisted configs should pin reviewed expected hashes. Never approve patient/episode notes as global policy.
- At the original conversion milestone, no Docker task had run. The later standalone bridge above now exercises actor MCP, while Harbor launcher integration still explicitly refuses unsupported execution. No simulator/judge/score/submission has run.
- Standalone case binding is now actor-observed with explicit selection. A patient ID exposed only after routing remains an unresolved reconciliation case; the guard currently blocks it.
- Healthcare decisions, semantic correctness, benchmark gains, provider retention and multi-tenant security are not established by these connection checks.
